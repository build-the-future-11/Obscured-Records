# Month 1 Execution Board — 29 September to 31 October 2026

This board converts the four-month operating plan into concrete work for the current repository. It is intentionally sequenced around the current owner-only deployment and the open public-launch gates.

## P0 — Public-launch certification

### Release ownership
- [ ] Name a release/incident owner.
- [ ] Name an editorial launch owner.
- [ ] Record who can change public audience/access.
- [ ] Record rollback authority and escalation path.

### Editorial launch selection
- [ ] Review the 28 existing public records for launch inclusion.
- [ ] Resolve claim-level gaps for the selected records.
- [ ] Confirm authorship/reviewer credits.
- [ ] Resolve Therac-25 image provenance.
- [ ] Resolve final Wirecard derivative provenance.
- [ ] Resolve Lake Nyos derivative provenance.
- [ ] Hold any record whose evidence or rights remain unresolved.

### Operations
- [ ] Assign a monitored intake operator.
- [ ] Run one controlled submission through acknowledgement → triage → closure.
- [ ] Assign retention/deletion responsibility.
- [ ] Perform provider-supported backup/restore rehearsal.
- [ ] Perform application rollback rehearsal with the named incident owner.
- [ ] Confirm recurring uptime/error monitoring.
- [ ] Reverify hosted WebP Content-Type.

### Device/accessibility
- [ ] Run representative physical-device review.
- [ ] Run representative screen-reader review.
- [ ] Record issues and block public expansion for any severe accessibility defect.

### Launch decision
- [ ] Freeze one exact candidate SHA.
- [ ] Run hosted CI on that SHA.
- [ ] Run exact live smoke checks.
- [ ] Write launch receipt with known limitations.
- [ ] Obtain editorial + operational sign-off.
- [ ] Only then change audience/public access.

## P1 — Editorial operating system

### Calendar
- [ ] Create a rolling four-week story calendar.
- [ ] Every story has a section, owner, editor, evidence requirement, rights status, deadline and distribution date.
- [ ] Limit active flagship stories to the number that can actually receive full review.

### First review queue
Start with a balanced queue; this is a review queue, not a publication order:

1. Mars Climate Orbiter — interface/unit failure.
2. Challenger — warning and decision process.
3. Columbia — evidence and imaging request process.
4. Hyatt Regency — load path and design change.
5. London Smog — ordinary fuel and public health system.
6. Bhopal — exposure beyond the factory boundary.
7. Love Canal — homes as environmental evidence.
8. Enron — entity structure and control.
9. Penn Central — short-term financing promise.
10. Port Chicago — labor, danger and military system.
11. Triangle Shirtwaist — exits and labor power.
12. Windscale — long-lived consequences after shutdown.

For each:
- [ ] map claims to exact sources;
- [ ] verify quotations, names, dates and causal wording;
- [ ] verify image/visual rights if used;
- [ ] identify what is original analysis versus source summary;
- [ ] identify missing voices or counter-evidence;
- [ ] record review outcome: revise / hold / approve.

### Corrections discipline
- [ ] Weekly corrections review.
- [ ] Material changes logged in the correction system.
- [ ] Source-link repairs are not mislabeled as claim recertification.

## P1 — Distribution foundation

### Search
- [ ] Define 8–12 topic clusters from the existing archive.
- [ ] Choose one pillar/flagship candidate per cluster.
- [ ] Add intentional internal-link plans.
- [ ] Record query/topic hypotheses before measuring performance.

### Newsletter
- [ ] Finalize The Obscured Brief template.
- [ ] Prepare four sample editorial issues without claiming send/delivery.
- [ ] Decide whether capture-only remains the accepted scope for Month 1.
- [ ] If sending is selected: choose provider, implement confirmation/unsubscribe/suppression, and test end to end before public promises.

### Story launch package
Create a template containing:
- canonical link;
- short excerpt;
- newsletter blurb;
- professional-network version;
- community/referral targets;
- visual/source card if rights allow;
- UTM fields;
- seven-day review date;
- thirty-day review date.

### Partnership pipeline
- [ ] Build a small, qualified list of publications/newsletters/communities.
- [ ] Track target → contacted → replied → active/declined.
- [ ] Do not count targets as partners.

## Definition of done

Month 1 is not done because a traffic target was written down. It is done when:

- the publication can safely expand beyond owner-only access;
- review and correction ownership are real;
- every approved story has a distribution path;
- measurements distinguish real current performance from historical context;
- the next month can operate from the board without relying on ad hoc founder memory.
