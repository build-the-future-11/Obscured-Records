# Obscured Records relaunch asset pack

Status: **DRAFT / PRE-LAUNCH**. This file packages launch-ready copy and dry-run artifacts. It does not authorize publication, deployment, newsletter delivery, audio/video upload, sponsor outreach, or production-data changes.

## 1. Truthful launch message

### One-line description

Obscured Records is an independent editorial archive for deeply sourced stories, historical records, and underreported events, built around source transparency, corrections, and durable evidence trails.

### Short launch announcement

Obscured Records is being relaunched around a simple editorial rule: the evidence trail should be visible, the uncertainty should stay visible, and corrections should remain part of the record. The archive brings together deeply sourced records across history, science, business, infrastructure, aviation, and public institutions. Each public record is intended to make its source path easy to inspect rather than asking readers to trust a polished summary alone.

The relaunch should be described as live only after the exact release-candidate revision has passed public smoke checks on the authoritative origin. Do not announce a newsletter cadence, audio channel, sponsor relationship, readership number, or contributor program as active without the corresponding retained receipt.

### Social launch copy

**Obscured Records, rebuilt around the evidence.**

Deeply sourced records. Visible source trails. Corrections that stay on the record. No manufactured urgency, no inflated audience claims, and no pretending a draft workflow is already a newsroom.

## 5. Contributor launch packet

A contributor receives one bounded record, not a standing newsroom title.

Minimum packet:

- assigned record / working slug;
- one-sentence scope;
- accountable editor;
- fact checker/reviewer;
- source packet location;
- claim-ledger template;
- rights/credit requirements;
- due date;
- public-claim boundary;
- definition of done;
- handoff location using `templates/EDITORIAL_HANDOFF.md`.

First two-week contributor proof should be one fully sourced artifact that survives independent fact check, not a volume target.

## 6. Submission acknowledgement copy

Use only after a real message is received through the monitored intake path:

> Thanks — I received your Obscured Records submission. Receipt does not imply acceptance or publication. I’ll review the source links and scope first. Please do not send confidential material by ordinary email. If I need clarification or additional documentation, I’ll reply in this thread.

For a correction or rights issue, add:

> I’ll treat this as a correction/rights review and preserve the current public record while the claim is checked. Any material correction will be logged according to the publication’s corrections policy.

Do not auto-send this copy until the intake route, ownership, and privacy handling are intentionally approved.

## 8. Analytics launch dashboard — specification only

The first useful dashboard should answer editorial questions without identifying readers:

- source-link click-through by source kind/host;
- newsletter submit attempt/success/failure by placement;
- search result-count bucket, without retaining query text;

- share action type;

No dashboard number becomes a public readership claim until the measurement window, event definition, exact deployed revision, and source receipt are retained.

## 9. Exact launch-day checklist

A public relaunch announcement is safe only after all of the following are true on one immutable release candidate:

- [ ] canonical CI and editorial-integrity gate are green;
- [ ] public contact links resolve to the intended monitored inbox;
- [ ] source links, media credits, corrections, standards, privacy, and submission pages are reviewed;
- [ ] canonical origin is singular and matches metadata, RSS, sitemap, public profiles, and smoke receipts;
- [ ] home, representative article, section, author, search, submit, newsletter, corrections, standards, RSS, sitemap, and robots paths pass smoke checks;
- [ ] newsletter copy does not imply delivery before end-to-end delivery exists;
- [ ] analytics remain unclaimed unless deployed receipts exist;
- [ ] sponsor inventory contains no unapproved public names/claims;
- [ ] no draft/held content leaks into public routes, RSS, sitemap, or search metadata;
- [ ] launch announcement is updated with the canonical URL only after the origin is frozen.

The minimum credible relaunch is the website plus truthful submission/correction paths. Newsletter delivery, analytics, audio/YouTube, sponsorship, and contributor expansion can remain gated after the website itself is ready.
