# Limitations and release blockers

**16 October 2026:** consult [canonical state](PROJECT_STATE.json) and [the website completion receipt](docs/WEBSITE_COMPLETION_2026-10-16.md) for the latest engineering pass. The earlier dated deployment identity below is historical. Lazy manuscript loading reduces initial data loading; imported shards remain cached, so no lifetime Worker memory guarantee or measured field-speed improvement is claimed.

1. **Editorial approval is open.** The 3,245 drafts are unassigned AI-assisted archival analyses or reconstruction plans, not verified original reporting. All four expansion manifests deliberately record their starting links as orientation sources, not claim-level evidence. Source metadata identifies what was located or inherited and the review tasks still required. Eight existing features and 20 existing public briefs were preserved; a working renderer does not recertify their factual claims. A real editor must assess structure, repetition, fairness, factual support and suitability before publishing each manuscript.
2. **Citation completeness is open.** The combined expansion audit confirms that all 3,200 subject-specific orientation URLs resolve; it does not verify a single material claim. The 15 October snapshot uses Wikipedia category membership and CC0 Wikidata descriptions for discovery, with exact page and entity revisions; those metadata are not primary evidence. The separate retained public-source audit tests 70 unique source URLs, not every claim or every outbound image URL. After repairing ten stale source references, 58 returned successful HTTP responses and 12 remained inaccessible to that automated client; no 404/410 remained in that run. Some source sites were readable through search/browser tools while rejecting the automated client. Replacements may be catalogues or overview pages, not proof of every narrative detail. Full tribunal/investigation documents and exact passages remain review tasks.
3. **Image rights and availability are unverified.** Existing externally hosted historical images and credits were retained. A credit is not a licence. Hotlinked images expose requests to third parties and may fail independently of the app; rights, stable hosting and optimized dimensions need an owner before release.
4. **Production persistence exists, but recovery and ownership remain unverified.** The owner-private Sites deployment has the expected `DB` binding and live tables for newsletters, submissions, rate limits and member data; earlier controlled production writes were verified. There is still no provider-supported backup/restore rehearsal, accepted retention/deletion owner or monitored operator workflow. Node/Vercel lacks the Workers D1 binding and intentionally returns 503 for intake.
5. **Newsletter delivery is absent.** Website capture saves pending confirmation. No confirmation-token flow, sending provider, authenticated sender, unsubscribe/suppression integration or delivery test exists. Existing active rows stay active; other signup states become pending, not sendable. No subscriber should be mailed from this database without a reviewed consent/suppression process.
6. **Live editorial operations are unverified.** No public admin dashboard was added. Repository access and an operator-only local CLI support review/triage. A named operator, controlled production access, actual inbox monitoring, acknowledgement dry run and retention practice remain necessary. No messages were sent.
7. **Abuse controls are bounded.** Honeypots, same-origin enforcement, size limits and durable counters reduce casual abuse. They do not authenticate sender ownership, stop a determined distributed attacker or prove DDoS resistance. A global cap can also deny legitimate traffic during a flood. Email hashes remain pseudonymous personal data.
8. **Accessibility and performance checks are scoped.** Automated browser checks cover keyboard/mobile navigation, labels, heading/skip targets, responsive overflow and error feedback. They are not a full WCAG audit, assistive-technology study, cross-browser matrix or field-performance certification. Browser timings mix warm/cold local cache states. External images were not redesigned or certified. The first local mobile homepage sample transferred about 3.43 MB from the same origin (including assets), mostly existing archival media; reducing media weight remains a performance improvement, not a measured field-speed claim.
9. **Private release identity exists; public release certification does not.** Owner-private Site version 25 is deployed from source `8e8cb6a4cb0ac1254353fe96ae5bd83f579fa107`, and environment revision 13 carries that same SHA. Deployment `appgdep_6ad0fa81ede88191abbf366f42e59a83` succeeded after an initial provider dependency-cleanup failure. Fresh read-only runtime checks confirm the served revision, 28-item RSS, a new draft's reader-route 404, editorial owner sign-in enforcement and anonymous HTTP 401. Access remains one owner only. The 3,245 unpublished manuscripts remain on the local expansion branch and private Site source; no public GitHub push occurred. The Site-source, local and GitHub commit IDs differ because they are separate repositories; dated receipts bind each exact revision. No owner-authenticated visual review of the expanded desk or public-release certification is claimed.
10. **Dependency security is verified at the recorded revision, not guaranteed indefinitely.** The committed production audit reports zero findings after updating Next.js, Sharp, source-map-js and fast-uri, and CI now fails on any production advisory at low severity or above. Advisory data and package support can change after this receipt, so future release candidates still require a fresh locked audit and the complete verification matrix.
11. **Optional channels remain plans.** Existing audio, analytics and sponsorship contracts were preserved. There is no actual audio player/episode, event-collector receipt, readership metric or sponsor relationship to claim. No research paper or experiment is applicable to this publication task.
